# 塔罗网站本地 Codex 集成设计

日期：2026-08-17

## 目标

让用户在 Windows 本机通过 ChatGPT 登录的 Codex SDK 使用塔罗网站，不填写 OpenAI API Key。交付同时包含：

1. 可重复启动的本地 Codex 服务；
2. 网站内置的“本地 Codex”引擎和无模型调用的连接检测；
3. 双击或单命令启动本地网站与服务。

这是一项本地个人使用功能，不把 ChatGPT Pro 额度导出成通用 API，也不声称能够观察具体额度扣减。

## 选定方案

在塔罗仓库内增加一个 Node.js 本地启动器。启动器只监听 `127.0.0.1:43127`，同时提供静态网站和 OpenAI 兼容接口。网页与接口使用同一来源，从而不依赖跨域、HTTPS 到 HTTP 或浏览器私有网络授权。

线上 GitHub Pages 仍可正常使用现有引擎；若在线页面选择“本地 Codex”，界面只提示用户运行本地启动器，不尝试绕过浏览器安全限制。

不采用以下方案：

- 独立端口中转站加线上网页直连：启动步骤更多，且受浏览器跨域和本地网络策略影响。
- Electron 等桌面封装：开发和维护成本超出本地个人使用需求。

## 组件与边界

### 本地启动器

- 位于塔罗仓库中，使用固定版本的 `@openai/codex-sdk`。
- 提供 `npm run local`，并提供 Windows 双击启动脚本。
- 启动前以无 shell 子进程检查 `codex login status`，仅接受精确的 `Logged in using ChatGPT`。
- 删除传给 Codex 子进程的 `OPENAI_API_KEY` 与 `CODEX_API_KEY`，不读取或记录它们的值。
- 固定 Codex 的 OpenAI provider、ChatGPT 登录方式、模型和低推理强度；浏览器提交的 `model` 字段不改变真实模型。
- 启动成功后自动打开 `http://127.0.0.1:43127/`；无法自动打开时打印该地址。
- 若固定端口已被占用，打印明确错误并退出；不静默改用其他端口。
- 退出时停止监听并中止正在运行的请求。

### HTTP 服务

提供三个路由：

- `GET /` 及静态资源：按明确的前端文件和素材目录白名单提供塔罗网页；拒绝路径穿越、点目录、`.git`、文档、依赖清单、测试及本地服务源码。
- `GET /health`：返回服务、ChatGPT 登录和固定模型的就绪状态；不得创建 Codex thread 或产生模型调用。
- `POST /v1/chat/completions`：接收网站现有的 OpenAI 兼容流式请求，创建一个新的 Codex thread，并返回 SSE content delta 和 `[DONE]`。

服务约束：

- 只绑定字面地址 `127.0.0.1`，不监听局域网接口。
- 校验 `Host`，并要求模型请求携带精确的同源浏览器 `Origin`；拒绝其他 Origin，也不返回跨域许可头。
- 同时只运行一个模型请求；并发请求返回 `429`，不排队、不重试。
- 请求体上限 128 KiB，组合提示词上限 64 KiB，响应上限 64 KiB。
- 每次请求有固定超时；浏览器断开时向 Codex runner 传递取消信号。
- 错误响应只返回稳定错误码，不暴露路径、环境变量、SDK 输出或堆栈。
- 关闭服务或失败不会自动重新调用模型。

### 网页集成

- AI 引擎下拉框新增 `本地 Codex（ChatGPT 登录）`。
- 本地 Codex 使用同源 `/v1/chat/completions`，沿用现有摘要与追问消息结构及 SSE 解析。
- 选择该引擎时隐藏 API Key、模型和自定义 URL 输入，避免制造可配置但实际被忽略的假象。
- 设置页新增“检测本地 Codex”按钮，仅请求 `/health`，显示“已连接”“未启动”或“请打开本地版本”。
- 本地 Codex 错误提示区分未启动、未登录、繁忙、超时和通用失败。
- 现有 provider、离线神谕、设置导入导出和线上部署行为保持兼容。

## 数据流

1. 用户运行 Windows 启动脚本或 `npm run local`。
2. 启动器确认 ChatGPT 登录，监听回环地址并打开本地网页。
3. 用户在设置中选择“本地 Codex”，连接检测调用 `/health`，不消耗模型额度。
4. 用户生成解读或发送追问时，网页向同源 `/v1/chat/completions` 发送一次流式请求。
5. 服务把现有消息按顺序扁平化成一个受限提示词，创建一个 Codex thread。
6. Codex 最终文本被封装为一条 SSE delta，再发送 `[DONE]`；网页按现有渲染流程显示文本。

每次网页请求对应至多一次 Codex 调用，不做隐式重试。追问历史由网页显式发送，不在服务端持久化。

## 测试与验收

默认验证全部离线，使用注入的假 runner，不调用模型：

- 请求解析、消息顺序、大小限制和浏览器断开取消；
- 健康检查不会调用 runner；
- 固定回环绑定、同源限制、并发拒绝、超时和错误脱敏；
- SSE 格式、中文内容和 `[DONE]`；
- 静态文件服务及路径穿越拒绝；
- 网页中本地 Codex 选项、字段显隐、连接检测和原 provider 回归；
- `node --check app.js`、TypeScript 类型检查和完整测试套件。

离线门禁通过后，单独请求用户授权一次真实网页端验收。该验收最多调用模型一次，不重试，并记录：HTTP 状态、SSE 完成标记、非空中文结果、本地端口状态和两个仓库的 Git 状态。未经该次授权不得调用模型。

## 完成标准

- 双击启动脚本或运行 `npm run local` 能打开本地塔罗网页。
- `/health` 在零模型调用下准确显示就绪状态。
- 网页选择本地 Codex 后不要求 API Key，并能完成摘要与追问请求路径。
- 服务不可从非回环接口访问，且不接受非同源浏览器请求。
- 所有离线测试和类型检查通过。
- 原有线上引擎与 GitHub Pages 静态使用方式无回归。
- 真实效果只在获得单独授权并完成一次端到端调用后标记为已验证。

## 非目标

- 公网、局域网或多人共享的中转服务；
- 通用 OpenAI API 兼容性或第三方程序支持；
- API Key、ChatGPT 凭据或 Codex 会话的导出；
- 自动重试、请求队列、后台常驻服务或开机启动；
- 证明或统计 ChatGPT Pro 的具体额度扣减。
